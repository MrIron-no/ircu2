# P11 Server-to-Server Protocol

This document describes **P11**, the eleventh revision of the ircu2
server-to-server (S2S) protocol. P11 is not a new protocol: it is P10 plus a
set of extensions that are negotiated **per link** and gated on the protocol
version each pair of servers agrees on. A P11 server speaks full P10 to a P10
peer and only enables P11 behaviour on links where both ends are P11.

For the base protocol — wire format, numerics, the token table, the net
burst, and every message P11 does not change — see [p10.md](p10.md). The
original historical P10 specification is preserved at
[history/p10.html](history/p10.html). This document covers only what P11 adds
or changes on top of P10.

## 1. Versioning

- Base version: `u2.11.0.0`.
- Major protocol version: `11` (`MAJOR_PROTOCOL` in `include/patchlevel.h`,
  derived from `AC_INIT` in `configure.ac`).
- Minimum protocol accepted at link time: `MINOR_PROTOCOL` in
  `include/ircd.h`. A peer announcing a lower version than this is refused
  during registration (`m_server.c`).

The major protocol number is the value carried in the `SERVER` handshake and
stored per link; the minor floor governs which old peers are still allowed to
link at all.

## 2. Negotiation

Each server announces its protocol in the `SERVER` message, as the `P` or `J`
token followed by the version — `P11` or `J11` for a P11 server (`J` while it
is still bursting, `P` once burst is complete; see [p10.md](p10.md) §4).

`parse_protocol()` (`m_server.c`) reads the announced number and clamps it to
this server's own `MAJOR_PROTOCOL`, so the value stored for a link is the
**minimum** of the two ends' capabilities. That stored value is the link's
negotiated protocol, reached everywhere through:

```c
Protocol(cptr)   /* == cli_serv(cptr)->prot, the negotiated link version */
```

A link between a P11 and a P10 server therefore negotiates to `10`, and the
P11 server transparently withholds every P11 extension on that link.

## 3. The gating principle

P11 replaces the old network-wide feature toggle with per-link protocol
gating. Where earlier extensions were switched on globally (a single
`FEAT_NETWORK_FEATURES`-style feature that had to be configured identically
across the network), a P11 extension is emitted to a peer only when that
peer's link speaks P11:

```c
if (Protocol(link) >= 11)
    /* ... emit or accept the P11 form ... */
```

This is symmetric with the long-standing `Protocol(x) < 10` checks that guard
the legacy P9/TS8 behaviour. It removes the need for a network-wide flag day:
each link independently uses the richest protocol both ends understand, and a
mixed P10/P11 network converges correctly without configuration.

Helpers that fan out to servers respect the negotiated version, e.g.
`sendcmdto_prot_serv_butone()` (`send.c`) sends only to links at or above a
given `min_prot`.

## 4. Implemented extensions

- **Protocol-gated S2S extension dispatch.** The core P11 change: S2S
  extensions are selected per link by `Protocol()` rather than by a global
  feature. (`s_serv.c`, `s_user.c`, `send.c`.)
- **User mode string variant.** `umode_str()` emits the P11 form to P11 links
  and the P10 form to P10 links (`s_serv.c`, `s_user.c`).
- **Labeled-response federation.** IRCv3 labeled-response capture and
  propagation across server links is gated on the link speaking P11: an
  inbound label is captured only from a P11 uplink, and a capture is handed
  off only to a P11 destination link (`parse.c`, `send.c`). See
  [readme.cap.md](readme.cap.md) for the client-facing capability.
- **Protocol 9 (P9/TS8) dropped.** `MINOR_PROTOCOL` is raised to `10`, so a
  peer announcing protocol 9 is refused at link time. The dead TS8 flag and
  the vestigial `CHFL_SERVOPOK` mechanism it fed are removed, as is the P9
  textual name-prefix parser in `parse_server()` (a numeric prefix is now
  the only server prefix form).

## 5. Proposed extensions

These are tracked as issues against the P11 revision and are **not yet
implemented**; listed here so the document is the single index of the P11
surface:

- Mandatory channel timestamp on `MODE` (`M`), removing the optional-TS
  heuristic.
- Burst ban setter and timestamp, so ban metadata survives a relink.
- Per-member delayed-join (`+D`) state carried in `BURST` (a per-member `d`
  flag) so hidden joins survive a netsplit.
- Splitting the `KILL` (`D`) path into its own parameter with a length cap, so
  a long path cannot truncate the reason.

Each proposed extension, when implemented, follows the gating principle in §3:
it is emitted only to `Protocol() >= 11` links and the P10 form is retained
for older peers.

## 6. Compatibility

- A P11 server is a full P10 server to every P10 peer; no P10 behaviour is
  removed or altered on a P10 link.
- No network-wide flag day is required: enabling P11 on one server enables it
  only on that server's P11 links.
- Protocol 9 (P9/TS8) is no longer supported: a P9 peer is refused at link
  time. The TS8 machinery it relied on carried no live behaviour by the P11
  era (its only consumer, server-op-ok, was already unused), so removing it
  changes nothing for P10 or P11 links.
